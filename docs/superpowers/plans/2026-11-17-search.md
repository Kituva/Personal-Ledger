# Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A search box at the top of Entries that finds entries from all months by any mix of date, amount, category and description, and shows what the matches add up to.

**Architecture:** The rules for reading a query and matching entries live in a new pure module, `src/search.js`, which has no React in it and is tested with vitest the way `sync.js` and `categories.js` are. `Entries` in `src/App.jsx` owns the query text. When the query is non-empty, it renders a new `SearchResults` component in place of its month stepper, chart, calendar and filters. `SearchResults` reuses `DayGroups` and `TxnRow`.

**Tech Stack:** React 18, Vite, vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-17-search-design.md`

## Global Constraints

- No new dependencies. `package.json` dependencies stay `react` and `react-dom`.
- The search input's font size is 16px or more, so iOS doesn't zoom the page when the box gets focus.
- Colours come only from the existing tokens in `src/styles.css` (`--surface`, `--surface2`, `--surface3`, `--text`, `--text2`, `--text3`, `--pos`, `--bg`).
- Copy, verbatim: placeholder `Search all entries`; button `Cancel`; reading line prefix `Looking for`; near note `Nothing for exactly ₹{amount}. These are the nearest amounts.`; count `1 entry` / `{n} entries`; empty `Nothing matches "{query}".`
- Numeric dates are read day first (`12/10/2025` is 12 October), matching the CSV importer.
- Commit messages follow the repo's style: a plain sentence with no `feat:` prefix, a body that explains why, and the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` line.
- Work on a branch, never directly on `main`. Pushing `main` deploys.

## Review Focus

1. **A day in the results with both spent and received entries.** Its day header must not add the two together. `DayGroups` uses `totalsOf` (Task 2) and shows them separately. This is checked in Task 3, step 5.
2. **An entry whose category has since been deleted** (`byId[t.cat]` is undefined). Search must not crash, and the entry should still match on its description. Tested in Task 2.
3. **A half-typed token** such as `₹`, `,` or `12/` must not produce `NaN` amounts or throw. Tested in Task 1.
4. **Editing or deleting an entry from the results** updates the results right away, and the search text survives the edit. Checked in Task 3, step 5.
5. **Cancel** restores Entries with the same month, filters and picked bar as before the search. Checked in Task 3, step 5.

### Task 1: Read a query into words

**Files:**
- Create: `src/search.js`
- Test: `src/search.test.js`

**Interfaces:**
- Produces:
  - `readQuery(text: string, opts?: { years?: Set<number> }) -> Word[]`
  - `Token = { text: string, amount: number | null, date: DateSpec | null }`, where `text` is lowercased.
  - `Word = { tokens: Token[], date: DateSpec | null, label: string }`. `date` is set only for a multi-token date phrase ("12 oct", "oct 2025"). A single-token word carries any date on its token.
  - `DateSpec = { y?: number, m?: number, d?: number }`, where `m` is 1–12.

**Rules the tests pin:**

- Split on whitespace. Strip trailing `,` and `.` from each token and drop tokens that end up empty.
- **Amount:** the token matches `/^₹?\d[\d,]*(\.\d+)?$/`. Remove `₹` and commas, then `Number()`. Anything else gives `amount: null`.
- **Month word:** at least 3 letters and a prefix of a full month name (`"oct"`, `"sept"`, `"october"`), giving `date: { m }`.
- **Numeric date:** `d/m`, `d-m`, `d/m/yyyy`, `d-m-yyyy` (day 1–31, month 1–12) or `yyyy-mm-dd`, giving `date` with the parts present.
- **Bare year:** a 4-digit token in `opts.years`. It gets `date: { y }` *and* keeps its `amount`.
- **Day** (for grouping only): an integer 1–31 with no `₹` and no commas. **Year** (for grouping only): 4 digits from 1900 to 2099.
- **Labels:** text gives `"petrol"` with the quotes. An amount gives `₹500`, formatted with `toLocaleString("en-IN", { maximumFractionDigits: 2 })`. A month alone gives `📅 any October`. A day and month give `📅 12 October`. A month and year give `📅 October 2025`. A full date gives `📅 12 October 2025`. A bare year in `years` gives `📅 2025 or ₹2,025`.

Grouping, left to right. The signature doesn't determine this, so here it is:

```js
// i walks the tokens; each pass emits one Word
if (isDay(t[i]) && isMonth(t[i + 1])) {        // "12 oct [2025]"
  take day = t[i], month = t[i + 1], j = i + 2;
  if (isYear(t[j])) take year = t[j++];
} else if (isMonth(t[i])) {                     // "oct [12] [2025]"
  take month = t[i], j = i + 1;
  if (isDay(t[j])) take day = t[j++];
  if (isYear(t[j])) take year = t[j++];
} else j = i + 1;                               // plain token
// tokens i..j-1 form one Word; if j - i > 1, Word.date = { y?, m, d? }
```

import { describe, it, expect } from "vitest";
import { readQuery } from "./search.js";

const labels = (q, o) => readQuery(q, o).map((w) => w.label);

describe("readQuery", () => {
  it("lowercases text and quotes it in the label", () => {
    const [w] = readQuery("Petrol");
    expect(w.tokens[0]).toEqual({ text: "petrol", amount: null, date: null });
    expect(w.label).toBe('"petrol"');
  });

  it("reads numbers as amounts, with or without ₹ and commas", () => {
    expect(readQuery("500")[0].tokens[0].amount).toBe(500);
    expect(readQuery("₹1,200")[0].tokens[0].amount).toBe(1200);
    expect(readQuery("499.50")[0].tokens[0].amount).toBe(499.5);
    expect(labels("₹1,200")).toEqual(["₹1,200"]);
  });

  it("reads month names of three letters or more, in any year", () => {
    expect(readQuery("oct")[0].tokens[0].date).toEqual({ m: 10 });
    expect(readQuery("sept")[0].tokens[0].date).toEqual({ m: 9 });
    expect(readQuery("October")[0].tokens[0].date).toEqual({ m: 10 });
    expect(readQuery("ma")[0].tokens[0].date).toBe(null);
    expect(labels("oct")).toEqual(["📅 any October"]);
  });

  it("joins a day written either side of a month", () => {
    for (const q of ["12 oct", "oct 12"]) {
      const ws = readQuery(q);
      expect(ws).toHaveLength(1);
      expect(ws[0].date).toEqual({ m: 10, d: 12 });
      expect(ws[0].label).toBe("📅 12 October");
    }
  });

  it("joins a year after a month, with or without a day", () => {
    expect(readQuery("oct 2025")[0].date).toEqual({ y: 2025, m: 10 });
    expect(labels("oct 2025")).toEqual(["📅 October 2025"]);
    expect(readQuery("12 oct 2025")[0].date).toEqual({ y: 2025, m: 10, d: 12 });
    expect(labels("oct, 2025")).toEqual(["📅 October 2025"]);
  });

  it("leaves a number that cannot be a day as its own word", () => {
    expect(labels("oct 500")).toEqual(["📅 any October", "₹500"]);
  });

  it("reads dates written in numbers, day first", () => {
    const full = { y: 2025, m: 10, d: 12 };
    expect(readQuery("12/10/2025")[0].tokens[0].date).toEqual(full);
    expect(readQuery("12-10-2025")[0].tokens[0].date).toEqual(full);
    expect(readQuery("2025-10-12")[0].tokens[0].date).toEqual(full);
    expect(readQuery("12/10")[0].tokens[0].date).toEqual({ m: 10, d: 12 });
    expect(labels("12/10/2025")).toEqual(["📅 12 October 2025"]);
  });

  it("reads a bare year as the year or the amount, only for years with entries", () => {
    const years = new Set([2025, 2026]);
    const [t] = readQuery("2025", { years })[0].tokens;
    expect(t.date).toEqual({ y: 2025 });
    expect(t.amount).toBe(2025);
    expect(labels("2025", { years })).toEqual(["📅 2025 or ₹2,025"]);
    expect(readQuery("2000", { years })[0].tokens[0].date).toBe(null);
    expect(labels("2000", { years })).toEqual(["₹2,000"]);
  });

  it("survives half-typed input", () => {
    expect(readQuery("   ")).toEqual([]);
    expect(readQuery(",")).toEqual([]);
    expect(readQuery("₹")[0].tokens[0]).toEqual({ text: "₹", amount: null, date: null });
    expect(readQuery("12/")[0].tokens[0].date).toBe(null);
  });
});

### Task 2: Match entries, and the nearest amounts

**Files:**
- Modify: `src/search.js`
- Test: `src/search.test.js`

**Interfaces:**
- Consumes: `readQuery`, `Word` and `Token` from Task 1.
- Produces:
  - `searchEntries(txns: Txn[], words: Word[], byId: Record<string, {name: string}>) -> { list: Txn[], near: number | null }`. `list` keeps the input order, and `App` already holds `txns` newest first. `near` is the amount that was loosened, or `null`.
  - `totalsOf(list: Txn[]) -> { spent: number, received: number }`
  - `Txn = { id, amount, type: "expense" | "income", cat, note, date: "YYYY-MM-DD" }`

**Rules the tests pin:**

- An entry matches when **every** word matches it. Empty `words` match nothing.
- A word matches when `word.date` matches the entry's date, **or** every one of its tokens matches. That second route is what keeps "oct 25" finding an October entry of ₹25 as well as the 25th of October.
- A token matches when any of these hold:
  - `text` is a substring of the lowercased category name (`byId[t.cat]?.name ?? ""`) or of the lowercased `note`
  - `amount` equals `t.amount` within 0.005
  - `date` matches
- A date matches when every part present in the `DateSpec` equals the same part of `t.date`.
- **Nearest amounts:** if the list is empty and any token has an `amount`, run again with amount checks loosened to `|t.amount - a| <= a * 0.1`. `near` is the first such token's amount. This happens only when the exact run found nothing.

import { readQuery, searchEntries, totalsOf } from "./search.js";

const CATS = {
  groc: { name: "Groceries" }, trans: { name: "Transportation" }, subs: { name: "Subscriptions" },
  personal: { name: "Personal" }, dining: { name: "Dining Out" }, sal: { name: "Salary" },
};
const t = (id, o) => ({ id, type: "expense", note: "", ...o });
const TXNS = [
  t("p1", { cat: "trans", note: "Petrol", amount: 500, date: "2026-10-14" }),
  t("d1", { cat: "personal", note: "Decathlon socks", amount: 2025, date: "2026-03-03" }),
  t("s1", { type: "income", cat: "sal", amount: 60000, date: "2025-12-01" }),
  t("n1", { cat: "subs", note: "Netflix 199 plan", amount: 649, date: "2025-11-02" }),
  t("g1", { cat: "groc", amount: 500, date: "2025-10-06" }),
  t("o25", { cat: "dining", note: "Tea", amount: 25, date: "2025-10-03" }),
  t("x1", { cat: "gone", note: "Plumber", amount: 499.5, date: "2025-09-09" }),
  t("p2", { cat: "trans", note: "Petrol", amount: 550, date: "2025-08-22" }),
];
const YEARS = new Set([2025, 2026]);
const run = (q) => searchEntries(TXNS, readQuery(q, { years: YEARS }), CATS);
const ids = (q) => run(q).list.map((x) => x.id);

describe("searchEntries", () => {
  it("matches part of a category name, in any case", () => {
    expect(ids("GRO")).toEqual(["g1"]);
  });
  it("matches the description", () => {
    expect(ids("petrol")).toEqual(["p1", "p2"]);
  });
  it("needs every word to match the same entry", () => {
    expect(ids("petrol oct")).toEqual(["p1"]);
  });
  it("matches an amount exactly, decimals included", () => {
    expect(ids("500")).toEqual(["p1", "g1"]);
    expect(ids("499.5")).toEqual(["x1"]);
  });
  it("matches a number inside a description", () => {
    expect(ids("199")).toEqual(["n1"]);
  });
  it("matches a month in any year, and the same letters as text", () => {
    expect(ids("dec")).toEqual(["d1", "s1"]);
  });
  it("matches a day and month in any year", () => {
    expect(ids("14 oct")).toEqual(["p1"]);
  });
  it("never lets the date reading hide the other one", () => {
    expect(ids("oct 25")).toEqual(["o25"]);
  });
  it("matches a bare year as the year, the amount or the text", () => {
    expect(ids("2025")).toEqual(["d1", "s1", "n1", "g1", "o25", "x1", "p2"]);
  });
  it("still matches an entry whose category was deleted", () => {
    expect(ids("plumber")).toEqual(["x1"]);
    expect(ids("gro")).toEqual(["g1"]);
  });
  it("falls back to amounts within 10% when nothing is exact", () => {
    expect(run("petrol 520")).toEqual({ list: [TXNS[0], TXNS[7]], near: 520 });
  });
  it("does not loosen when something is exact", () => {
    expect(run("petrol 500")).toEqual({ list: [TXNS[0]], near: null });
  });
  it("does not loosen without a number", () => {
    expect(run("zzz")).toEqual({ list: [], near: null });
  });
  it("matches nothing for no words", () => {
    expect(searchEntries(TXNS, [], CATS)).toEqual({ list: [], near: null });
  });
});

describe("totalsOf", () => {
  it("keeps money spent and money received apart", () => {
    expect(totalsOf([TXNS[0], TXNS[4], TXNS[2]])).toEqual({ spent: 1000, received: 60000 });
  });
});

- Produces: `Search` icon (`() => <svg>`, 17px, a magnifier: `circle cx=10.5 cy=10.5 r=6.5` and a line from `15.5,15.5` to `20,20`, using the file's `svg()` helper); `SearchResults({ txns, q, onTap })`.

**Behaviour to build** (spec section "What changes for you"):

- `Entries` gains `q` (string) and `active` (boolean) state and an input ref. The search row is the first thing in `.scroll`, above `PeriodNav`.
- `searching = q.trim() !== ""`. While searching, `Entries` renders `<SearchResults txns={txns} q={q} onTap={onTap} />` instead of `PeriodNav`, the header, `Bars`, `SpendGrid`, `Filters`, the picked-bar pill and `DayGroups`. Its hooks still run every render, unconditionally.
- While searching, the `day` passed to `onDay` is `null`, so + adds an entry dated today.
- The input has `type="search"`, `enterKeyHint="search"`, `autoCapitalize="off"`, `autoCorrect="off"`, `spellCheck={false}` and `aria-label="Search all entries"`. Enter blurs it, which dismisses the keyboard.
- The ✕ inside the box shows when `q` is non-empty. It clears `q` and refocuses the input.
- **Cancel** shows when `active || searching`. It clears `q`, sets `active` false and blurs the input. Nothing else in `Entries` is reset, so the month, filters and `sel` survive.
- Starting or stopping a search scrolls to the top: `useEffect(() => window.scrollTo(0, 0), [searching])`.
- `SearchResults` builds `years` from `txns` and memoises `readQuery` and `searchEntries` on `[q, txns, byId]`. It renders, in order:
  - The reading line `Looking for` followed by one `.readchip` per `word.label`.
  - The near note, when `near !== null`.
  - The total card: the count on the left and the money on the right. With only spent entries it shows `₹{money(spent)}`. With only received entries it shows `+₹{money(received)}` in `--pos`. With both, it shows `₹{spent} spent` above `+₹{received} received`, the latter in `--pos`.
  - `DayGroups` over `list`.
  
  When `list` is empty, it shows the empty copy instead of the card and the list.
- If `list` covers more distinct days than `DayGroups`' `limit` (120), it adds a `.empty`-styled line under the list: `Showing the newest 120 days of matches. Add a word to narrow it down.`
- `DayGroups`' day header uses `totalsOf(rows)`. When a day has received entries as well as spent ones, it shows `₹{spent} · +₹{received}` with the second part in `--pos`. Days with one kind look exactly as they do now.
- CSS classes: `.searchrow`, `.searchbox` (`--surface2`, pill radius, 44px tall, with `:focus-within` drawing a 1.5px `--surface3` ring), `.searchbox input` (16px, no border or background, `outline: none`, with `::-webkit-search-cancel-button` hidden), `.searchclear`, `.searchcancel`, `.reading`, `.readchip`, `.restotal`, `.nearnote`. Take the values from the `search-flow` mockup in `.superpowers/brainstorm/1141-1794896753/content/search-flow.html`.
